# Contract Protocol Source Label 01

## Professional defect and boundary

The deployed application generated an editable two-page disagreement protocol
from the current owner workspace. A read-only, full-page render showed that two
proposals grounded in an unnumbered source document had the same generic
"unnumbered clause" label. The original wording and source name appeared in
other columns, but the clause-reference column did not identify the document.
That makes a protocol row harder to negotiate or trace to its source. This is
a document-assembly defect; it is not authority to reinterpret Qwen's contract
analysis or to invent clause numbers.

## Reusable correction

For an unnumbered source clause, the protocol now prefixes its exact source
document name to the existing page-aware reference. Numbered clauses keep
their source-supported number. The column is called "Пункт договора /
документа" because a proposal may refer to an admitted contract attachment.
The candidate wording, source text, issue and revision identities are
unchanged. Controlled tests use changed document names and assert that a
model-generated working key never becomes an official clause number.
The reviewed-package validator uses the same source-bound label and updated
table header, so a legitimate protocol is not rejected as stale merely
because its professional label improved.

## Bounded acceptance

The source render of the same owner-scoped protocol remains two pages and
is legible on both pages; the formerly ambiguous rows now carry their
document name. The unchanged deployed release's assessment, revised-source
package members and protocol were all rendered in full: 35, 30, 7 and 2
pages, respectively. Every page contained extractable text; minimum counts
were 158, 129, 290 and 2,581 characters, respectively. This detects empty
pages but does not certify legal correctness or every page's visual layout.
The corrected protocol was regenerated through the application service from
the same owner-scoped structured view, reopened and visually checked on both
pages. The revised-source package also regenerated without a mapping error.
The contractor proposals remain review candidates, not accepted amendments.

## Multi-source numbered-clause integrity follow-up

Numbered clauses in different admitted documents may use the same number.
The protocol therefore now includes the source document for *every* proposal,
not only unnumbered ones. The reviewed-source package validates the exact
document-bound protocol rows. A changed two-document fixture with identical
clause number, original text and proposed text passes with correct source
labels and rejects a forged protocol that attributes the second row to the
first document. The source-reference column was widened without changing the
overall table width. A read-only owner-scoped render reopened as two pages;
both pages were visually inspected and remain readable. No project fact or
proposal was changed, and no Qwen job was submitted for this deterministic
integrity correction.
