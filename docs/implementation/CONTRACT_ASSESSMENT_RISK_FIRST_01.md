# Contract Assessment Risk-First 01

## Observed product defect

The current owner-scoped editable contract assessment rendered to 35 pages.
Its first page began with raw procurement/commercial condition rows; the
contractor risks and proposed changes came only after a long source and
obligation inventory. The risk table also displayed internal codes such as
`contract_risk`, `payment_dependency` and `candidate` as ordinary user text.
That is a direct professional-output defect, not a missing queue or model job.

## Reusable correction

The assessment now leads with its existing contractor risks and proposals,
then key conditions and project cross-checks. Source-reference and obligation
inventories remain in full later in the same editable document. A finite,
generic label map presents existing contract-risk taxonomy and applicability
in Russian; unknown machine codes fall back to an explicit generic label,
while already human-readable values remain unchanged. No risk, quantity,
clause or proposed wording is generated by this formatting change.

## Bounded acceptance

A changed-contract unit case verifies the professional section order and that
known internal codes do not appear as table labels. Focused source checks
passed 70/70. A read-only application-service render against the current
owner workspace remained 35 pages, with no near-empty page across the full
document. Its first page now contains contractor risk rows with professional
Russian labels; the first page was visually inspected. This is not a legal
opinion on Qwen's underlying proposals or an owner-authenticated browser
download acceptance.
