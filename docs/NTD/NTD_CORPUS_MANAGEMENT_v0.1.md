## 0. Что подтверждено, а что нет (проверено перед написанием документа)

Перед фиксацией провайдера страница была открыта, а не принята на
слово — дисциплина, которой репозиторий уже следует
(`docs/NTD/README.md`, ADR-0003):

- `https://minstroyrf.gov.ru/docs/419099/` — подтверждено: это карточка
  **конкретно СП 543.1325800.2024** (дата публикации 27 декабря 2024
  года), с кнопками «Посмотреть»/«Скачать» и прямой ссылкой на
  официальный PDF. Это **не реестр** всех СП — страница одного документа.
- `https://minstroyrf.gov.ru/docs/` — подтверждено: общий раздел
  документов Минстроя (более 8870 документов), с фильтрами по типу
  (в т.ч. «Свод правил») и по статусу («действующие»/«проекты»), без
  видимой прямой строки поиска по обозначению на этой странице.
- **Не подтверждено** и не выдумывается: точные URL страниц СП 70 и
  СП 48 на сайте Минстроя, точные действующие редакции и даты СП 70 и
  СП 48. Ниже они помечены `[ИСТОЧНИК НЕ ПОДТВЕРЖДЁН]` — по аналогии с
  правилом `~/MAC_ASD/CLAUDE.md` («никогда не придумывать номера или
  названия документов; если точный документ не найден — явная пометка»),
  которое здесь применяется и к этому репозиторию, хотя формально
  относится к другому проекту.

## 1. Назначение

Дополняет `docs/NTD/README.md` (правила именования и хранения файлов)
процедурой **приобретения**: откуда корпус НТД пополняется, как
проверяется подлинность и актуальность, и когда это требует, а когда не
требует участия человека (`docs/product/PRODUCT_OPERATING_MODEL_v0.1.md`
§3).

## 2. Первичный официальный провайдер

**Минстрой России**, `minstroyrf.gov.ru`, раздел «Документы»
(`minstroyrf.gov.ru/docs/`) — признан первичным официальным провайдером
для стартового корпуса СП (раздел 3) по совокупности подтверждённых
признаков: домен государственного органа (`.gov.ru`), министерство —
орган, утверждающий своды правил, прямая публикация оригинального PDF с
датой на самом сайте (не через посредника), открытый доступ без
авторизации (подтверждено разделом 0).

Это решение зафиксировано **только для стартового корпуса** (СП 70,
СП 543, СП 48). Провайдер для остальных типов НТД (ГОСТ Р, СНиП,
ведомственные нормы) этим документом не определяется — открытое решение
(раздел 7, OD-NTD-04).

## 4. Алгоритм автоматической загрузки

Ровно семь шагов из задания, детализированные до уровня, воспроизводимого
исполнителем (человеком или будущим адаптером):

1. **Определить требуемый документ и редакцию.** Вход — обозначение
   (например, «СП 543») и, если известна, требуемая дата действия
   (`study.study_date`, `asd_kontur.domain.study.StudyOfConstructionObject`).
   Источник запроса — распознанная ссылка на НТД в ПД/РД или потребность
   правила `R-APL-02` (`docs/product/DETERMINISTIC_RULES_MODEL_v0.1.md` §3)
   подтвердить конкретную действующую редакцию.
2. **Найти официальный URL Минстроя.** Через фильтр «Свод правил» +
   «действующие документы» на `minstroyrf.gov.ru/docs/`, либо встроенный
   поиск сайта (не проверен, раздел 7, OD-NTD-02). Для СП 543 — уже
   подтверждённый прямой URL (раздел 0). **Не хардкодить непроверенные
   URL** для документов, не прошедших проверку раздела 0.
3. **Скачать файл.** HTTP-запрос по найденному URL кнопки «Скачать»;
   проверка `Content-Type: application/pdf`; временное сохранение до
   хеширования.
4. **Вычислить SHA-256.** Та же схема, что и для остального корпуса
   (`TECHNICAL_ARCHITECTURE_v0.2.md` §5.3, §4.3 — контент-адресуемое
   хранилище) — НТД не получает отдельной схемы адресации.
5. **Извлечь текст и пагинацию.** Для последующего построения
   `SourceLocator` (номер страницы/пункта,
   `asd_kontur.domain.sources.SourceLocator`). Конкретный экстрактор —
   вне объёма этого документа: относится к раздельному контуру
   OCR/извлечения (`TECHNICAL_ARCHITECTURE_v0.2.md` §7), не к процедуре
   приобретения как таковой.
6. **Сохранить метаданные и локальный путь.** Регистрация как
   `SourceDocument`/`SourceVersion` (`source_type =
   NORMATIVE_TECHNICAL_DOCUMENT`) с `content_hash` из шага 4; локальный
   путь — в корпусе на MBP (`TECHNICAL_ARCHITECTURE_v0.2.md` §4: MBP —
   площадка контура извлечения и разового импорта, не VPS `kat-core`).
7. **Перед применением правила сверить редакцию и изменения.** Правило
   `R-APL-02` (`DETERMINISTIC_RULES_MODEL_v0.1.md` §3) проверяет
   `EffectivePeriod` загруженной версии против даты события и наличие
   официально опубликованных «Изменений» к документу — автоматическая
   загрузка не заменяет эту проверку, только ускоряет получение
   источника для неё (раздел 6).

## 5. Когда исключение «нужен доступ» НЕ создаётся, и когда создаётся другое исключение

**Не создаётся** ручное исключение «нужен доступ» для СП 70, СП 543,
СП 48 и их официально опубликованных изменений — источник открытый,
без авторизации, без платного доступа (подтверждено разделом 0);
загрузка обязана быть автоматической, ручной шаг «сначала кто-то должен
получить доступ» для этих трёх документов не создаётся вообще.

**Создаётся** исключение (закрытый перечень
`docs/product/AUTOMATION_AND_EXCEPTIONS_v0.1.md` §4.3) только при:

| Ситуация | Ближайший существующий подтип §4.3 |
|---|---|
| Фактическая техническая ошибка загрузки (сеть, HTTP-ошибка, таймаут) | нет точного соответствия — см. раздел 7, OD-NTD-03 |
| Файл отсутствует у официального источника (страница удалена, документ не найден в каталоге) | 3.3 «отсутствие обязательного основания» |
| Неопределённость редакции (несколько версий без ясного статуса «действующая», конфликт дат) | 3.1/3.6 «конфликт версий» / «применимость спорна» |

«Техническая ошибка загрузки» не покрывается ни одним существующим
подтипом дословно — `AUTOMATION_AND_EXCEPTIONS_v0.1.md` §4 прямо
запрещает расширять перечень без пересмотра самого документа
(«список не расширяется добавлением новых подтипов без пересмотра этого
документа»). Этот документ **не редактирует** утверждённый перечень —
фиксирует потребность как открытое решение (раздел 7, OD-NTD-03), а до
его формального добавления такая ошибка классифицируется по ближайшему
подтипу 3.4 («нечитаемость») как временное решение, не как постоянная
классификация.

## 6. Инвариант: открытый источник не отменяет проверку применимости

Автоматическая загрузка ускоряет **получение** источника — не заменяет
и не сокращает проверку его **применимости**. Зарегистрированная
`SourceVersion` с вычисленным хешем проходит те же правила R-APL-01/
R-APL-02, что и любой другой источник корпуса
(`docs/architecture/DOMAIN_CORE_SPEC_v0.1.md` §7.1): шесть измерений
применимости, дата, переходные положения. «Скачано автоматически с
официального сайта» не эквивалентно «применимо без проверки».

## 7. Открытые решения

- **OD-NTD-01** — точные подтверждённые действующие редакции СП 70 и
  СП 48 (раздел 3) — не проверены в рамках этой задачи, требуют отдельной
  проверки перед первой реальной загрузкой.
- **OD-NTD-02** — механизм программного поиска URL на
  `minstroyrf.gov.ru` (встроенный поиск сайта, его URL-схема, наличие
  публичного API) — не проверен; без него шаг 2 алгоритма для СП 70/
  СП 48 не автоматизировать буквально, только вручную по каталогу.
- **OD-NTD-03** — добавление в закрытый перечень
  `docs/product/AUTOMATION_AND_EXCEPTIONS_v0.1.md` §4.3 нового подтипа
  «техническая ошибка автоматической загрузки НТД» — требует отдельного
  пересмотра того документа, не решается здесь.
- **OD-NTD-04** — провайдер для НТД вне стартового корпуса (ГОСТ Р,
  СНиП, ведомственные нормы) — Минстрой признан первичным только для
  СП 70/543/48 этой редакцией.
