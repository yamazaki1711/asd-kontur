# НТД — нормативно-техническая документация

Хранилище нормативных документов, применяемых как источник обязательных требований
доменного ядра АСД-КОНТУР.

## Что здесь хранится

Файлы PDF действующих и исторических норм:

- СП (своды правил);
- СНиП;
- ГОСТ и ГОСТ Р;
- ведомственные и отраслевые нормы, регламенты, методики.

## Правила именования файлов

```
<ТИП>-<обозначение>_<год редакции>_<краткое название>.pdf
```

Примеры:

```
СП-70.13330.2012_Несущие_и_ограждающие_конструкции.pdf
ГОСТ-Р-21.101-2020_СПДС_Основные_требования_к_проектной_и_рабочей_документации.pdf
СНиП-3.03.01-87_Несущие_и_ограждающие_конструкции.pdf
```

Требования к имени:

- обозначение приводится полностью, включая номер редакции и год;
- пробелы заменяются подчёркиванием;
- при наличии изменений к документу указывается редакция с изменениями:
  `..._с_Изм_1_2.pdf`;
- недействующая редакция не удаляется, а помечается суффиксом `_ОТМЕНЁН`.

## Чего здесь нет

- извлечённых требований и правил их применения — они относятся к спецификациям
  доменного ядра, а не к хранилищу первоисточников;
- проектной и рабочей документации объектов (ПД/РД);
- регламентов заказчика по исполнительной документации.

## Связь с доменным ядром

НТД — один из четырёх входов доменного ядра наравне с ПД/РД, договорными требованиями
и регламентом заказчика. Любая ссылка машинного вывода на норму должна указывать
конкретный файл этого каталога, его редакцию и пункт — согласно
`docs/architecture/decisions/0003-offline-and-traceability.md`.

## Ограничения хранения

Файлы крупнее 50 МБ вызывают предупреждение GitHub, крупнее 100 МБ — отклоняются.
Такие документы размещаются вне репозитория, а здесь остаётся ссылка на их расположение.
