# Функциональные срезы и приёмочные сценарии

Каталог `docs/mvp/` сохраняет историческое имя пути. Материалы Support в
нём описывают внутренний вертикальный срез, а не границу MVP или готовности
АСД-КОНТУР. По ADR-0007 готовность продукта требует сквозной готовности
`Tender`, `Support`, `Audit` и `Restoration`.

## Цель

Проверить на одном ограниченном фрагменте реального ОКС сквозную цепочку:

> РД → МТР → входной контроль → выполнение работы → лаборатория/геодезия → АОСР и исполнительные схемы → комплект папки → КС.

## Рабочий пилот

Один объект или конструктив, несколько технологически связанных видов работ и один завершённый производственный период.

## Минимальные участники

- прораб;
- инженер ПТО;
- геодезист;
- лаборатория;
- строительный контроль;
- администратор объекта.

## Критерии готовности Support-среза функциональной модели

- определены роли, права и зоны ответственности;
- описаны основные и исключительные сценарии;
- задан жизненный цикл МТР, работы, контроля и документа;
- определены блокирующие события и предупреждения;
- описана офлайн-работа полевого клиента и синхронизация;
- определены обязательные сущности и их связи;
- перечислены экраны первой версии;
- каждый критерий приёмки проверяем на пилотных данных;
- явно разделены детерминированные правила, ИИ-функции и решения человека.

Выполнение этого списка не означает готовности продукта: для каждого из
четырёх режимов дополнительно обязательны собственные inputs, common-kernel
process, `RuleSetVersion`, outputs, uncertainties/blockers, authorities, E2E
tests и terminal readiness condition.

## Требуемый пилотный пакет

1. ПД/РД выбранного фрагмента.
2. Смета или ВОР.
3. Регламент ИД заказчика.
4. Фактическая папка ИД.
5. Документы на материалы.
6. Журналы, протоколы и исполнительные схемы.
7. Перечень участников и подписантов.
8. Текущая таблица учёта ПТО.
