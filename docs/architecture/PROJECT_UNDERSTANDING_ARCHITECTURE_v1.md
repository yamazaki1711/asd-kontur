# Project Understanding Architecture v1

PD/RD—especially the explanatory note—is the primary workspace source for OKS
purpose/class/characteristics, structure, zones/axes/levels/fronts, design
solutions, work types/dependencies/quantities, materials, project requirements,
NTD references and geometry. The system does not ask the user for facts already
available in admitted source evidence.

Extraction produces candidates with exact SourceVersion/locator. Deterministic
validation and human/professional authority create verified project facts. The
versioned result is:

`ProjectDefinition → ConstructionWorkPackage → WorkRequirementMatrix`.

VOR/estimate and contract/regulation are reconciled against this common model,
not parsed into separate mode truth. Customer requirements may add controls,
evidence or copies but cannot weaken NTD or leak across workspaces. Missing
official NTD remains a typed gap and prevents normative confirmation, while
operations not requiring that authority may continue.

Current code supplies contracts and a synthetic bounded chain only. Real
document classification, hierarchy, quantities/material extraction and
representative E2E are below `CAPABILITY_READY`.
